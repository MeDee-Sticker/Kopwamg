# 01 — Facebook Page + การโพสต์อัตโนมัติ

เป้าหมายของไฟล์นี้: ให้เพจ Facebook ของ Kopwang พร้อมใช้งาน และให้สคริปต์ `scripts/fb_scheduler.py`
โพสต์จากแผน 30 วันได้จริง

> สรุปสั้น ๆ ก่อนเริ่ม: **การสร้างเพจทำผ่านหน้าเว็บของ Facebook เท่านั้น** Meta ไม่มี API สำหรับสร้างเพจใหม่
> (เอนด์พอยต์ `POST /{business_id}/owned_pages` ใช้ "อ้างสิทธิ์เพจที่มีอยู่แล้ว" ไม่ใช่สร้างใหม่)
> ส่วนที่ automate ได้คือ "การโพสต์" หลังจากมีเพจและโทเคนแล้ว

---

## ขั้นที่ 1 — สร้างเพจ (ทำมือ ประมาณ 5 นาที)

1. ล็อกอิน Facebook ด้วยบัญชีส่วนตัวของคุณ (ต้องมีบัญชีส่วนตัวก่อนสร้างเพจ)
2. ไปที่ **Pages → Create** หรือ `https://www.facebook.com/pages/create`
3. กรอกข้อมูล:
   - **ชื่อเพจ:** `Kopwang | ระบบสร้างรายได้ใน 30 วัน`
   - **หมวดหมู่:** Digital creator (หรือ สินค้าและบริการ / การศึกษา)
   - **คำโปรย:** คัดลอกจาก `brand/brand-kit.md` หัวข้อ 2
4. อัปโหลดรูปโปรไฟล์ (โลโก้) และรูปหน้าปก — ใช้ชุดภาพเดียวกันกับ TikTok และ Shopee
   ไฟล์: `brand/social/profile/facebook-profile-1024.png` และ `brand/social/cover/facebook-cover-851x315.png`
   (ขั้นตอนและโซนปลอดภัยดู `brand/social/README.md`)
5. ตั้งปุ่ม CTA ของเพจเป็น **"ส่งข้อความ"** และวางลิงก์ Line OA ไว้ในส่วนติดต่อ
6. เพิ่มลิงก์ Line OA ในส่วน "ลิงก์" ของเพจ แล้วซ่อนลิงก์อื่นที่ไม่จำเป็น
7. (แนะนำ) สร้าง Business Portfolio ใน Meta Business Suite แล้วเพิ่มเพจเข้าไป เพื่อจัดการสิทธิ์ในอนาคต

**เช็กลิสต์ก่อนไปขั้นต่อไป**

- [ ] เพจมองเห็นได้แบบสาธารณะ ไม่ได้ซ่อน
- [ ] บัญชีของคุณเป็นแอดมินเพจ (มีสิทธิ์สร้างเนื้อหา)
- [ ] รูปโปรไฟล์และหน้าปกไม่ใช่รูปที่ติดลิขสิทธิ์

---

## ขั้นที่ 2 — สร้างแอป Meta และเปิดสิทธิ์โพสต์

1. เข้า `https://developers.facebook.com/apps` → **Create App**
2. เลือก use case ที่เกี่ยวกับการจัดการเพจ (**Manage everything on your Page** / Pages API)
3. เพิ่มผลิตภัณฑ์ **Facebook Login for Business** (ใช้สำหรับขอสิทธิ์) และ **Pages API**
4. ใน App Settings → Basic ให้กรอก Privacy Policy URL และข้อมูลแอปให้ครบ (Meta มักบังคับก่อนใช้สิทธิ์)
5. แอปของคุณจะอยู่โหมด Development ซึ่งใช้ได้กับบัญชีที่มีบทบาท (role) ในแอปเท่านั้น
   — สำหรับ "โพสต์เพจของตัวเอง" แบบนี้เพียงพอ ไม่ต้องยื่น Business Verification

**สิทธิ์ที่ต้องขอ**

| สิทธิ์ | ใช้ทำอะไร |
|---|---|
| `pages_show_list` | ดูรายการเพจที่คุณจัดการ เพื่อดึง Page ID |
| `pages_manage_posts` | โพสต์/ตั้งเวลา/แก้ไข/ลบโพสต์ของเพจ (สิทธิ์หลักที่ต้องมี) |
| `pages_read_engagement` | อ่านโพสต์และข้อมูลปฏิสัมพันธ์ของเพจ |

---

## ขั้นที่ 3 — ขอ short-lived user token

1. เปิด **Graph API Explorer** (`https://developers.facebook.com/tools/explorer/`)
2. เลือกแอปของคุณ แล้วเลือก **Get User Access Token**
3. ติ๊กสิทธิ์ `pages_show_list`, `pages_manage_posts`, `pages_read_engagement` (และ `business_management` ถ้ามี)
4. กดยืนยันในหน้าต่างที่เด้งขึ้น (ต้องล็อกอินด้วยบัญชีที่เป็นแอดมินเพจ)
5. คัดลอกโทเคนที่ได้ — โทเคนนี้มีอายุสั้น (ไม่กี่ชั่วโมง)

---

## ขั้นที่ 4 — แลกเป็นโทเคนอายุยาว + ดึง Page token

สร้างไฟล์ `.env` ที่รากโปรเจกต์ (คัดลอกจาก `.env.example`) แล้วใส่ `FB_APP_ID` และ `FB_APP_SECRET`
จาก App Settings → Basic จากนั้นรัน:

```bash
python3 scripts/fb_scheduler.py --exchange-token "โทเคนที่คัดลอกมาจากขั้นที่ 3"
```

สคริปต์จะพิมพ์ค่าที่ต้องนำไปใส่ใน `.env` ให้:

```env
FB_PAGE_ID=...
FB_PAGE_ACCESS_TOKEN=...
```

> ⚠️ `FB_APP_SECRET` และโทเคนทุกตัวเป็นความลับ **ห้ามคอมมิตไฟล์ `.env`** (มี `.gitignore` กันไว้แล้ว)
> และห้ามวางลงหน้าบราวเซอร์หรือโพสต์ในแชท
> โทเคนผู้ใช้อายุยาวประมาณ 60 วัน (Meta ไม่รับประกันอายุที่แน่นอน) — ตั้งเตือนในปฏิทินทุก 45 วันเพื่อต่ออายุ

## ขั้นที่ 5 — ตรวจการเชื่อมต่อ

```bash
python3 scripts/fb_scheduler.py --check
```

ควรเห็นชื่อเพจ หมวดหมู่ และจำนวนคนติดตามตรงกับเพจที่สร้าง ถ้าขึ้น error ว่าไม่มีเพจ
ให้ตรวจว่าบัญชีที่ล็อกอินเป็นแอดมินเพจ และได้ติ๊กสิทธิ์ `pages_show_list` ตอนอนุญาต

## ขั้นที่ 6 — โพสต์หรือตั้งเวลา

```bash
# ดูตัวอย่างโพสต์ของวันนี้ โดยไม่ยิงเข้า API (dry-run เป็นค่าเริ่มต้นเสมอ)
python3 scripts/fb_scheduler.py --today

# โพสต์จริงเฉพาะวันนี้
python3 scripts/fb_scheduler.py --today --live

# โพสต์จริงวันที่ 5
python3 scripts/fb_scheduler.py --day 5 --live

# มอบหมายให้ Facebook ตั้งเวลาโพสต์ที่เหลือทั้งหมด (วันที่ 6-30)
python3 scripts/fb_scheduler.py --schedule --from-day 6 --to-day 30 --live
```

**ข้อจำกัดที่ต้องรู้เรื่องการตั้งเวลา**

- Meta รับเวลาโพสต์ล่วงหน้าได้ **10 นาที ถึง 30 วัน** เท่านั้น ถ้าเลยกำหนด สคริปต์จะเปลี่ยนเป็นโพสต์ทันทีให้เอง
- ทุกครั้งที่โพสต์สำเร็จ สคริปต์จะบันทึกใน `state/fb_state.json` ทำให้รันซ้ำวันเดิมได้โดยไม่โพสต์ซ้ำ
- ถ้าต้องการโพสต์ซ้ำวันที่ทำไปแล้ว ให้ลบรายการนั้นออกจาก `state/fb_state.json` ก่อน

ถ้าอยากให้โพสต์ไปนั่งเป็น "ร่าง" ใน Facebook เพื่อตรวจบนหน้าจอก่อน ดูขั้นที่ 6.4

---

## ขั้นที่ 6.4 — สร้างโพสต์ร่าง (unpublished) จากไฟล์ในเครื่อง

ถ้าอยากตรวจโพสต์บนหน้าจอ Facebook จริงก่อนเผยแพร่ ให้สร้างเป็น **โพสต์ unpublished**
จากไฟล์ร่างใน `content/drafts/` — ใช้ Page token ใน `.env` ตัวเดียวกับขั้นที่ 4 ไม่ต้องพึ่งเครื่องมือเชื่อมต่ออื่น:

```bash
# 1) ดูว่าจะส่งอะไรไป (dry-run — ไม่ยิง API)
python3 scripts/fb_scheduler.py --draft --file content/drafts/fb-001-page-intro.md

# 2) สร้างโพสต์ unpublished จริง
python3 scripts/fb_scheduler.py --draft --file content/drafts/fb-001-page-intro.md --live

# ทางเลือก: ใช้แคปชันของวันในแผน ไม่ใช้ไฟล์ร่าง
python3 scripts/fb_scheduler.py --draft --day 5 --live
```

สคริปต์ส่ง `POST /{page-id}/feed` ด้วย `published=false` และ `unpublished_content_type=DRAFT`
แล้วอ่านโพสต์กลับมาตรวจ `is_published` ว่าเป็น `false` จริง

| เรื่อง | พฤติกรรม |
| --- | --- |
| ที่ตรวจร่าง | Meta Business Suite → Content → Drafts (เดสก์ท็อป) หรือค้นด้วย post id ที่สคริปต์พิมพ์ |
| ขึ้นเพจหรือไม่ | ไม่ขึ้นเพจจนกว่าคุณกดเผยแพร่เอง — สคริปต์ไม่ publish และไม่ตั้งเวลาให้ |
| กันสร้างซ้ำ | บันทึกใน `state/fb_state.json` หัวข้อ `drafts` — รันซ้ำจะข้าม ใช้ `--force` เมื่อต้องการสร้างใหม่ |
| ด่านคอนเทนต์ | แคปชันว่าง, ยาวเกิน 2,200 ตัวอักษร หรือมีคำสัญญารายได้ จะถูกปฏิเสธก่อนยิง API |
| สิทธิ์ที่ต้องมี | `pages_manage_posts` และ Page access token (เหมือนการโพสต์ปกติ) |
| ไฟล์ร่างต้องมี | หัวข้อ `## แคปชัน (คัดลอกวางได้เลย)` แล้วตามด้วยข้อความโพสต์ (ดูตัวอย่างใน `content/drafts/`) |

> ข้อจำกัดของ Meta: โพสต์ข้อความล้วนและรูปหลายรูปแสดงใน Drafts บนเดสก์ท็อป
> ส่วนรูปเดี่ยวมีรายงานว่าไม่ขึ้นใน Drafts (ยังเปิดได้จาก post id) และมือถืออาจไม่แสดง Drafts
> ถ้าไม่เห็นใน Drafts ให้ใช้ post id ที่สคริปต์บันทึกไว้ตรวจผ่าน Graph API หรือเปิดบนเดสก์ท็อป

### ดูและตรวจสถานะร่างภายหลัง

```bash
# ดูรายการร่างจาก state (ไม่ยิง API)
python3 scripts/fb_scheduler.py --list-drafts

# ตรวจกับ Facebook ว่าแต่ละร่างยังอยู่ไหม
python3 scripts/fb_scheduler.py --verify-drafts
```

`--verify-drafts` อ่านโพสต์ทีละใบด้วย Page token แล้วรายงานทีละรายการ:

| สถานะ | ความหมาย | สิ่งที่ควรทำ |
| --- | --- | --- |
| ยังเป็นร่าง (unpublished) | `is_published=false` | เปิดตรวจใน Business Suite แล้วกดเผยแพร่เองเมื่อพร้อม |
| เผยแพร่แล้ว | `is_published=true` | ไม่ต้องสร้างใหม่ — ถ้าเป็นร่างที่ผูกกับวันในแผน สคริปต์บันทึกเป็นโพสต์ของวันนั้นให้แล้ว |
| ไม่พบใน Graph API | ถูกลบ หรือ token ไม่มีสิทธิ์อ่านโพสต์ unpublished | เปิด Business Suite ดูอีกครั้ง; ถ้าต้องการใหม่ใช้ `--force` |
| ตรวจไม่ได้ | token หมดอายุ/สิทธิ์ไม่พอ/เครือข่ายขัดข้อง | แก้ตามข้อความ error (มักต้อง `--exchange-token` ใหม่) |

- ผลตรวจถูกเขียนลง `state/fb_state.json` (`status`, `checked_at`, `status_changed_at`) — `--list-drafts` จึงแสดงสถานะล่าสุดได้โดยไม่ต้องยิง API
- คำสั่งนี้เป็นการอ่านอย่างเดียวบน Facebook ไม่ต้องใช้ `--live` แต่ต้องมี `FB_PAGE_ID` และ `FB_PAGE_ACCESS_TOKEN`
- exit code `0` = ตรวจได้ครบทุกรายการ (รวมกรณี "ไม่พบ") · `1` = มีรายการที่ตรวจไม่ได้
- **ไม่ต้องรันเองทุกวัน:** `scripts/daily_run.sh` เรียก `--verify-drafts` ก่อนโพสต์ทุกครั้ง และเขียนผลลง `state/logs/draft-status-YYYY-MM.log` (หัวข้อถัดไป)

### ตรวจอัตโนมัติทุกวันผ่าน daily_run.sh

`scripts/daily_run.sh` ตรวจสถานะร่างให้ก่อน แล้วจึงโพสต์ของวันนี้ ผลตรวจจะถูกต่อท้าย log รายเดือน
โดยไม่มีอะไรทับของเดิม:

```text
state/logs/draft-status-2026-10.log

=== 2026-10-18 09:00:03 +0700 ===
ตรวจสถานะร่าง 2 รายการกับ Graph API (อ่านอย่างเดียวบน Facebook)

  ✅ day:5 (id 111_222): ยังเป็นร่าง (unpublished)
  ✅ file:fb-001-page-intro (id 333_444): เผยแพร่แล้ว (is_published=true)
    🔔 เปลี่ยนสถานะ: ยังเป็นร่าง (unpublished) → เผยแพร่แล้ว

สรุป: ยังเป็นร่าง 1 · เผยแพร่แล้ว 1 · ไม่พบ 0 · ตรวจไม่ได้ 0
เปลี่ยนสถานะจากการตรวจครั้งก่อน 1 รายการ

🔔 ร่างที่ต้องตรวจสอบ:
  - file:fb-001-page-intro: เผยแพร่แล้ว
```

- เตือนเฉพาะเมื่อสถานะ **เปลี่ยนจากครั้งก่อน** (หรือเพิ่งพบครั้งแรกว่าเผยแพร่/หลุด) จึงไม่ซ้ำทุกวัน
- ถ้าร่างที่ผูกกับวันในแผนถูกเผยแพร่แล้ว วันนั้นจะถูกบันทึกใน `published` ทำให้โพสต์ของวันนั้นไม่ถูกโพสต์ซ้ำ
- ถ้าตรวจไม่ได้ (โทเคนหาย/หมดอายุ) งานโพสต์ยังทำงานต่อ แต่จะพิมพ์บรรทัดเตือนและบันทึกเหตุผลลง log
- กำหนดโฟลเดอร์ log อื่นได้ด้วย `DAILY_LOG_DIR=/path/to/logs ./scripts/daily_run.sh --live`

## ขั้นที่ 6.5 — โพสต์จากหน้าเว็บปฏิทิน (ทางเลือก ถ้าไม่อยากพิมพ์คำสั่ง)

ถ้าอยากกดโพสต์จากหน้าเว็บ `dashboard/index.html` แทนการพิมพ์คำสั่งในเทอร์มินัล:

```bash
# เปิดเซิร์ฟเวอร์ในเครื่อง (ผูกกับ 127.0.0.1 เท่านั้น)
python3 scripts/dashboard_server.py --live
```

แล้วเปิด `http://localhost:3000` → คลิกการ์ดวัน → แท็บ Facebook → กล่องด้านล่างจะมี 2 แถว

| แถว | ปุ่ม | ทำอะไร |
| --- | --- | --- |
| โพสต์ | "ทดลองโพสต์" / "โพสต์ขึ้นเพจทันที" | ดูข้อความก่อน / โพสต์จริง (ถามยืนยัน 1 ครั้ง) |
| ตั้งเวลา | "ทดลองตั้งเวลา" / "ตั้งเวลาโพสต์ล่วงหน้า" | ดูว่าจะตั้งเวลาเมื่อไร / ตั้งเวลาจริงตามวันและเวลาในแผน |
| ร่าง | "ทดลองสร้างร่าง" / "สร้างโพสต์ร่าง (unpublished)" | ดูว่าจะส่งอะไรไป / สร้างโพสต์ unpublished เพื่อตรวจใน Meta Business Suite → Content → Drafts (ถามยืนยัน 1 ครั้ง) |

แถว "ร่าง" คือคำสั่ง `--day N --draft` ในสคริปต์ — ใช้แคปชันของวันนั้นจาก `content/plan.json`
สร้างเป็นโพสต์ unpublished (ไม่ขึ้นเพจ) แล้วขึ้นสถานะ "มีร่าง unpublished แล้ว (id …)" บนการ์ด
เมื่อมีร่างของวันนั้นแล้ว ปุ่มจะถูกล็อกเพื่อกันสร้างร่างซ้ำ (ถ้าต้องการสร้างใหม่ให้ใช้ `--force` ผ่าน CLI)
ส่วนการสร้างร่างจากไฟล์ใน `content/drafts/` ยังใช้คำสั่ง `--draft --file ...` ตามขั้นที่ 6.4

แถว "ตั้งเวลา" คือคำสั่ง `--day N --schedule` ในสคริปต์ ใช้เวลาโพสต์จาก `content/plan.json`
โดยตรง (ไม่ต้องกรอกเอง) แล้วขึ้นป้าย "FB ตั้งเวลาไว้" บนการ์ด — วันที่ตั้งเวลาแล้วจะยังไม่ถูก
นับว่าทำแล้ว จนกว่าโพสต์จะขึ้นเพจจริง

ปุ่มที่เขียนข้อมูลจริง (โพสต์ ตั้งเวลา และสร้างร่าง) จะกดได้เฉพาะเมื่อโทเคนใน `.env` ครบและเซิร์ฟเวอร์
เปิดด้วย `--live` ส่วนปุ่มทดลองใช้ได้แม้ยังไม่มีโทเคน

ข้อจำกัดที่หน้าเว็บบังคับไว้ให้:

- ตั้งเวลาได้เฉพาะวันและเวลาที่ยังไม่ผ่าน และต้องล่วงหน้าอย่างน้อย 10 นาที — ถ้าเลยกำหนดแล้ว
  หน้าเว็บจะล็อกปุ่มและชี้ไปที่ปุ่ม "โพสต์ขึ้นเพจทันที" แทน (ไม่แอบโพสต์ทันทีให้)
- ตั้งเวลาได้ไม่เกิน 30 วันล่วงหน้า (ข้อจำกัดของ Meta)
- วันที่โพสต์หรือตั้งเวลาไปแล้วจะตั้งซ้ำไม่ได้ เพราะจะได้โพสต์ซ้ำในเพจ
- ร่างของวันหนึ่งสร้างซ้ำไม่ได้ (กันร่างซ้ำในเพจ) — ถ้าต้องการสร้างใหม่ให้ใช้ `--force` ผ่าน CLI
- ปุ่มเขียนข้อมูลทุกปุ่ม (รวมสร้างร่าง) ถามยืนยันก่อนทำงาน และรับคำสั่งจาก origin เดียวกันเท่านั้น (กัน CSRF)

ถ้าต้องการตั้งเวลาหลายวันพร้อมกันยังใช้ CLI ได้เหมือนเดิม:

```bash
python3 scripts/fb_scheduler.py --schedule --from-day 6 --to-day 30 --live
```

## ขั้นที่ 7 — ให้ระบบโพสต์เองทุกวัน (cron)

```bash
# เปิด crontab
crontab -e

# แนะนำ: ตรวจสถานะร่างอัตโนมัติ + โพสต์ของวันนี้ ทุกวัน 09:00 น. (เวลาเครื่องที่รันสคริปต์)
0 9 * * * cd /path/to/kopwang && ./scripts/daily_run.sh --live >> state/daily-run.log 2>&1
```

`daily_run.sh` รวมงาน 3 อย่างไว้ในคำสั่งเดียว:

1. สร้าง `content/plan.json` ใหม่ ถ้ายังไม่มี
2. ตรวจสถานะโพสต์ร่างกับ Facebook และเขียนผลลง `state/logs/draft-status-YYYY-MM.log`
3. โพสต์ Facebook ของวันนี้ แล้วแสดงงานมือที่เหลือของวัน

```bash
./scripts/daily_run.sh          # ทดลอง (dry-run) — ยังตรวจสถานะร่างให้ด้วย
./scripts/daily_run.sh --live   # โพสต์จริง
```

> ถ้าตั้ง cron ให้เรียก `fb_scheduler.py --today --live` ตรง ๆ จะข้ามการตรวจสถานะร่าง
> ทำให้ไม่รู้ว่าร่างใดถูกเผยแพร่หรือหลุด — ใช้ `daily_run.sh` เป็นค่าเริ่มต้น

## เรื่องที่ต้องระวัง

- **Rate limit:** การเรียกด้วย Page token ใช้โควตาแบบ Business Use Case ซึ่งคำนวณจาก `4,800 × จำนวนคนที่ปฏิสัมพันธ์กับเพจใน 24 ชม.` สคริปต์จะพิมพ์ค่าโควตาจากเฮดเดอร์ให้เห็น และถอยหลังอัตโนมัติเมื่อเจอ error 32 / 613 / HTTP 429
- **ห้ามโพสต์รัวเพื่อไล่ตามแผน:** วันละ 1 โพสต์คือแผนที่ถูกออกแบบไว้แล้ว
- **ข้อความต้องผ่านนโยบายโฆษณาและชุมชน:** ห้ามสัญญารายได้ ห้ามอ้างผลลัพธ์เกินจริง
- **ถ้าเปลี่ยนเพจ:** รัน `--exchange-token` ใหม่เพื่อดึง Page token ของเพจใหม่
